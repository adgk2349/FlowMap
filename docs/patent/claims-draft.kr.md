# 청구항 초안

주의: 아래 청구항은 기술 초안이다. 실제 출원용 청구항은 변리사가 선행기술 조사, 공개일, 국가별 소프트웨어 발명 심사기준을 반영해 재작성해야 한다.

## 청구항 1: 방법 독립항

1. 컴퓨터에 의해 수행되는, AI 생성 코드 변경의 구조적 불일치 검출 방법에 있어서,
   소프트웨어 프로젝트의 복수의 소스 파일을 파싱하여 파일 노드, 타입 노드, 함수 노드 및 호출 엣지를 포함하는 현재 작업공간 그래프를 생성하는 단계;
   버전 관리 시스템으로부터 변경된 소스 파일을 식별하는 단계;
   상기 변경된 소스 파일의 기준 버전 내용을 파싱하여 제1 그래프 fragment를 생성하는 단계;
   상기 변경된 소스 파일의 현재 작업트리 내용을 파싱하여 제2 그래프 fragment를 생성하는 단계;
   상기 현재 작업공간 그래프 중 상기 변경된 소스 파일에 속하지 않는 노드 및 엣지를 포함하는 context graph를 이용하여 상기 제1 그래프 fragment 및 상기 제2 그래프 fragment 각각의 unresolved call site를 해석하는 단계;
   상기 해석된 제1 그래프 fragment와 상기 해석된 제2 그래프 fragment를 비교하여 추가 노드, 제거 노드, 변경 노드, 추가 엣지 및 제거 엣지 중 적어도 하나를 포함하는 그래프 차분을 생성하는 단계;
   상기 그래프 차분에 포함된 노드 또는 엣지를 기초로 영향 분석 시작 노드를 결정하는 단계;
   호출 엣지의 역방향을 따라 상기 영향 분석 시작 노드로부터 영향 노드를 산출하는 단계; 및
   상기 그래프 차분 및 상기 영향 노드를 사용자 인터페이스에 표시하는 단계를 포함하는 방법.

## 청구항 2: 변경 파일 fragment

2. 청구항 1에 있어서,
   상기 기준 버전 내용은 Git 저장소의 HEAD 버전으로부터 획득되고,
   상기 현재 작업트리 내용은 저장되지 않았거나 커밋되지 않은 현재 파일 내용으로부터 획득되는 방법.

## 청구항 3: 신규 파일 처리

3. 청구항 1에 있어서,
   상기 기준 버전에 존재하지 않는 신규 파일은 상기 제1 그래프 fragment 생성 단계에서 제외되어 제거 노드로 잘못 산출되지 않도록 하는 방법.

## 청구항 4: Context-aware call resolution

4. 청구항 1에 있어서,
   상기 unresolved call site를 해석하는 단계는,
   상기 context graph와 상기 그래프 fragment를 결합한 resolution context로부터 workspace-wide symbol index를 생성하고,
   상기 workspace-wide symbol index를 이용하여 상기 unresolved call site의 호출 대상 후보를 결정하는 방법.

## 청구항 5: 보수적 해석

5. 청구항 4에 있어서,
   상기 호출 대상 후보가 정확히 하나인 경우에만 호출 엣지를 생성하는 방법.

## 청구항 6: 수신자 기반 규칙

6. 청구항 4에 있어서,
   상기 unresolved call site를 해석하는 단계는,
   대문자로 시작하는 base expression을 명시적 타입 수신자로 판단하여 타입명 및 함수명 쌍으로 method index를 조회하고,
   `self` base expression을 caller type 및 함수명 쌍으로 method index를 조회하고,
   base expression이 없는 호출을 함수명으로 global function index에서 조회하고,
   lowercase variable base expression을 갖는 호출은 타입이 불확실한 것으로 판단하여 해석하지 않는 방법.

## 청구항 7: 그래프 차분

7. 청구항 1에 있어서,
   상기 그래프 차분을 생성하는 단계는,
   노드 식별자가 제2 그래프 fragment에만 존재하는 경우 추가 노드로 분류하고,
   노드 식별자가 제1 그래프 fragment에만 존재하는 경우 제거 노드로 분류하고,
   노드 식별자가 양쪽에 존재하되 노드의 이름, 종류, URI 또는 라인 정보 중 적어도 하나가 상이한 경우 변경 노드로 분류하는 방법.

## 청구항 8: 엣지 차분

8. 청구항 1에 있어서,
   상기 그래프 차분을 생성하는 단계는,
   엣지의 시작 노드, 종료 노드 및 종류를 포함하는 복합 키가 제2 그래프 fragment에만 존재하는 경우 추가 엣지로 분류하고,
   상기 복합 키가 제1 그래프 fragment에만 존재하는 경우 제거 엣지로 분류하는 방법.

## 청구항 9: 영향 시작 노드

9. 청구항 1에 있어서,
   상기 영향 분석 시작 노드를 결정하는 단계는,
   추가 노드 및 변경 노드 중 적어도 하나를 시작 노드로 포함하고,
   제거 노드를 호출하던 caller 노드를 시작 노드로 포함하고,
   추가 호출 엣지의 caller 노드를 시작 노드로 포함하는 방법.

## 청구항 10: 직접 변경과 간접 영향 분리

10. 청구항 1에 있어서,
    상기 사용자 인터페이스에 표시하는 단계는,
    상기 그래프 차분에 의해 직접 변경된 노드와 상기 호출 엣지의 역방향 탐색에 의해 산출된 간접 영향 노드를 서로 다른 표시 상태로 표시하는 방법.

## 청구항 11: contains edge 제외

11. 청구항 1에 있어서,
    상기 영향 노드를 산출하는 단계는 파일-타입 또는 타입-함수 포함 관계를 나타내는 contains edge를 영향 전파 대상에서 제외하는 방법.

## 청구항 12: IDE 연동

12. 청구항 1에 있어서,
    상기 사용자 인터페이스는 IDE extension에 의해 제공되고,
    소스 파일 저장 이벤트, 명령 팔레트 실행, 또는 컨텍스트 메뉴 실행 중 적어도 하나에 응답하여 상기 방법이 수행되는 방법.

## 청구항 13: AI 생성 코드 검토

13. 청구항 1에 있어서,
    상기 그래프 차분 및 상기 영향 노드는 AI 코딩 도구에 의해 생성 또는 수정된 코드 변경의 구조적 환각 후보를 검토하기 위해 표시되는 방법.

## 청구항 14: 시스템 독립항

14. AI 생성 코드 변경의 구조적 불일치 검출 시스템에 있어서,
    하나 이상의 프로세서; 및
    상기 하나 이상의 프로세서에 의해 실행되는 명령을 저장하는 메모리를 포함하고,
    상기 명령은 상기 하나 이상의 프로세서로 하여금:
    소프트웨어 프로젝트의 소스 파일을 파싱하여 현재 작업공간 그래프를 생성하고,
    변경된 소스 파일의 기준 버전과 현재 버전을 각각 graph fragment로 생성하고,
    변경되지 않은 작업공간 context를 이용하여 상기 graph fragment의 unresolved call site를 해석하고,
    상기 기준 버전 graph fragment와 현재 버전 graph fragment 사이의 그래프 차분을 생성하고,
    호출 엣지의 역방향 전파를 통해 영향 노드를 산출하고,
    상기 그래프 차분 및 상기 영향 노드를 표시하도록 하는 시스템.

## 청구항 15: 비일시적 기록매체

15. 하나 이상의 프로세서에 의해 실행될 때 청구항 1 내지 청구항 13 중 어느 한 항의 방법을 수행하도록 하는 명령을 저장한 비일시적 컴퓨터 판독 가능 기록매체.

## 추가 종속항 후보

16. 청구항 1에 있어서, 상기 소스 파일은 Swift 파일이고, 상기 파싱은 SwiftSyntax 기반 AST parser를 이용하는 방법.

17. 청구항 1에 있어서, 상기 표시 단계는 추가 요소, 제거 요소, 변경 요소 및 영향 요소를 서로 다른 색상, 테두리 또는 선 스타일 중 적어도 하나로 표시하는 방법.

18. 청구항 1에 있어서, 상기 현재 작업공간 그래프는 파일 노드, 타입 노드, 함수 노드, contains edge 및 calls edge를 포함하는 방법.

19. 청구항 1에 있어서, 상기 그래프 차분은 JSON payload로 IDE extension에 전달되는 방법.

20. 청구항 1에 있어서, 상기 영향 노드 산출은 순환 호출 관계에서도 무한 반복을 방지하기 위해 visited set을 유지하는 방법.

## 권리범위 전략 메모

넓은 독립항:

- 특정 언어, VS Code, SwiftSyntax, Git에 과도하게 제한하지 않는다.
- "AI 생성 코드"를 목적/사용 맥락으로 넣되, 방법의 기술 구성은 graph diff + context-aware resolution + impact propagation으로 잡는다.

좁은 종속항:

- SwiftSyntax
- Git HEAD/current working tree
- VS Code extension
- 색상/테두리 UI
- 보수적 cross-file resolution 규칙

변리사와 상의할 포인트:

- "AI hallucination" 표현을 청구항에 직접 넣을지, 명세서 목적/효과에만 둘지
- 한국/미국/일본/유럽 각각의 소프트웨어 발명 적격성 대응
- 이미 공개된 자료를 고려한 청구항 범위 조정
